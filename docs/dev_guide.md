# Developer notes

How to work on this repository. The code is the reference implementation of
published results. Every figure in the paper is generated by a notebook from
the package, and every random draw is seeded.

## uv

The project is managed with [uv](https://docs.astral.sh/uv/). It creates the
virtual environment, installs the dependencies and runs the commands, so
`pip`, `conda` and `venv` are not needed.

**Install**

```bash
# Unix (macOS/Linux)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

```{caution}
If a conda base environment is active, run `conda deactivate` first. Otherwise `uv` can pick
up the wrong Python.
```

**Set up and run**

```bash
# Install the package with the development tools and the documentation build
uv sync --all-extras

# Run commands in the project environment
uv run pytest
uv run jupyter lab

# Or activate the environment
source .venv/bin/activate  # Unix
.venv\Scripts\activate     # Windows
```

**Add dependencies**

```bash
uv add <package>                  # a runtime dependency
uv add <package> --optional dev   # a development tool
uv add <package> --optional docs  # for the documentation build
```

Use `uv add` instead of editing `pyproject.toml` by hand, so that `uv.lock` matches it. Python
is pinned to 3.13 in `.python-version`.

## Checks

Run these four commands on the whole tree before you commit:

```bash
uv run ruff check .      # lint; notebooks included
uv run ruff format .     # format; notebooks are excluded, see pyproject.toml
uv run pyright           # types, standard mode, over src/, tests/ and the notebook helpers
uv run pytest            # the test suite; pure algebra and synthetic input, no data needed
```

[Ruff](https://docs.astral.sh/ruff/) is configured in `pyproject.toml`.
The naming rules `N802`, `N803`, `N806` and `N812` are off, so that the symbols
of the paper (`R`, `Gx`, `Sigma`, `p0`) can be used as names. Every other name
is `snake_case`.

```{note}
In VS Code or Cursor, install the Ruff extension. Pylance reads the `[tool.pyright]`
section of `pyproject.toml`, so the editor and the command line report the same
diagnostics.
```

## pre-commit

[pre-commit](https://pre-commit.com/) runs the same four checks, `uv lock` and
the whitespace hooks on every commit. Install the Git hook once:

```bash
uv run pre-commit install
```

If a hook changes a file (ruff reformatting, a missing trailing newline), the
commit stops. Look at the change, stage it and commit again. To run all hooks
on the whole tree:

```bash
uv run pre-commit run --all-files
```

To update the hook versions: `uv run pre-commit autoupdate`.

## Tests

The suite in `tests/` uses pure algebra and synthetic input and does not read
`data/`. It checks the errors that would otherwise pass unnoticed: the algebraic
invariants (commutativity, skew-symmetry, equinorm, path independence), the
closed-form similarity function of Eq. 4, known-answer cases, and that every
sampling function is seeded. The models are small and the seeds fixed, so the
suite runs in under a minute.

## Notebooks

The notebooks in `notebooks/` reproduce the figures of the paper and record the
experimental fitting. They are stored with their outputs, and the documentation
build does not run them. To run one again:

```bash
uv run jupyter nbconvert --to notebook --execute --inplace notebooks/<name>.ipynb
```

Figures are written to `figures/`, which is not tracked. The CA1 notebooks read
`data/ca1_events.npz`, which is tracked. [The data page](../data/README.md)
explains how to rebuild it from the raw recordings.

## Documentation

The documentation is a [Jupyter Book (version 1)](https://jupyterbook.org/v1/).
The book root is the repository root, so the notebooks are included in place:

- `_toc.yml` defines the structure. The notebooks follow the order of the figures.
- `_config.yml` holds the configuration. Notebook execution is off. The API reference is
  generated from the NumPy-style docstrings by `sphinx.ext.autodoc` and `napoleon`.
- `docs/` holds the other pages, the API reference pages included.

To build it locally:

```bash
uv run jupyter-book build .
open _build/html/index.html
```

The online documentation is built on every pull request and deployed to
GitHub Pages on every push to `main`.
